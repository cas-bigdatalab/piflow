# Dataset QA 验证

在项目根目录、已安装项目依赖与 pytest 的 Python 环境执行：

```powershell
python -m pytest scientific_agents/dataset_qa/tests -q --disable-warnings --tb=short
```

运行时代码不依赖本目录。模型决策使用脚本与真实工具 schema 校验；MCP 覆盖模拟故障和本地 FastMCP 协议集成。模型请求次数可验证，生产模型遵循率和线上服务延迟需在部署环境评估。

## 受控检索

`test_bounded_discovery.py` 覆盖实际服务流程，`test_search_policy.py` 覆盖计数与分页边界。

- 实际返回并去重后至少六条才满足候选数量要求；上游 `total` 不能替代实际记录。
- 最多四个不同关键词。翻页、同词重试不增加关键词数量，失败不计作空结果。
- 关键词先从用户请求提取原文主题，再补充同义词、翻译等改写。运行时校验原词确实来自当前或历史用户消息，并保证当前请求原词优先、所有原词先于改写词；两类合计最多四词。模型输出顺序错误会在本地纠正，不增加 MCP 或模型调用。
- 同一查询的页面没有新记录时停止翻页；页面大小和页码遵守 MCP schema。
- 结果计数与展示使用相同的稳定标识规则；完整原始结果仍保存，合并结果保留逐条来源映射。
- 检索列表与详情共同交付时，仍合并检索分页并保留详情；后续对第六个候选等序号的引用指向实际展示的去重列表。
- 四个关键词完成后，零条与一至五条候选使用不同的答复依据；超时、预算耗尽或错误中断不会标为四次空查询。
- 验证第二页恢复、唯一结果 ID、取消、跨轮次隔离、精确查询、明确操作，以及科研流程的前置步骤不会提前结束后续操作。

## 能力适配

`capabilities.Profile.search` 声明检索词参数、分页参数、结果列表、总数位置及稳定标识路径。`atomic` 声明可作为明确单步操作的能力。现有 piflow 工具通过 QA 内部适配表接入；其他 MCP 可在 `meta.piflow.qa` 提供同样的描述，无需依靠工具名称或领域关键词猜测。

适配后的模型工具参数包含 `__qa_task`：

- `complete_request=true`：该操作可以完成整个当前请求；运行时建立执行目标，成功后直接交付。
- `complete_request=false`：这是后续操作的前置步骤，继续交给计划与工具决策处理。
- 检索中的 `keywords`：主题检索的关键词计划，通常一次提供四个相关短语；运行时按需执行，到达门槛立即停止。精确查询必须显式使用 `null`。
- 检索中的 `original_keywords`：从用户原请求提取的主题短语，保留原语言与用词，属于 `keywords` 的一部分；精确查询使用 `null`。历史调用缺失此字段时，只从用户原文识别来源，不把模型生成的翻译冒充原词。

这些参数在调用 MCP 之前移除。MCP 原始 schema、传输重试和对象引用校验仍有效。自动扩展只接管声明只读且幂等的检索能力。未采用适配描述的工具保留通用执行路径。

复杂任务应先声明必要成果，再执行各步骤。关键词变化和翻页不是新的成果；已有检索不能通过后补目标、精确查询标记或辅助结果身份绕过完成条件。

## 用户答复

`test_request_grounding.py` 验证原词顺序、来源校验、提前结束和跨轮主题；`test_public_labels.py` 验证诊断恢复后的业务名称、未提供名称的安全省略、不可用答复及会话重放。

能力适配可通过 `Profile.label` 提供用户可理解的名称。错误恢复中的任务描述优先采用错误出现前的原始意图，随后采用适配声明的名称；无法确定名称时省略，不生成“待处理事项 N”。工具只返回错误而没有可确认原因时，说明本次未取得对应内容，不建议盲目稍后重试或调整检索范围，也不推断永久不支持。后台诊断和真实执行状态继续单独保存；这层答复不增加模型请求或 MCP 调用。

这种组合采用明确任务的受控执行路径，同时保留复杂任务的动态规划。参考 [Anthropic 的工作流与智能体实践](https://www.anthropic.com/research/building-effective-agents) 和 [LangGraph 工作流与智能体模式](https://docs.langchain.com/oss/python/langgraph/workflows-agents)。
